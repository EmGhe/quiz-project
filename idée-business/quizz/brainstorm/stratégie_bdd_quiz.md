# Stratégie de contenu — Plateforme de quiz

## 1. Objectif

Construire une base de questions de quiz **très importante, continuellement enrichie et régulièrement mise à jour**, destinée principalement à un public français.

La base doit être :

* vaste ;
* variée ;
* fiable ;
* accessible au grand public ;
* intéressante et divertissante ;
* culturellement équilibrée ;
* régulièrement renouvelée ;
* capable d'intégrer automatiquement de nouvelles informations.

L'objectif à long terme est de pouvoir atteindre **des dizaines  de milliers, voire centaines de questions**, sans sacrifier leur qualité.

Le contenu doit être pensé pour donner envie aux utilisateurs de revenir régulièrement jouer.

---

## 2. Public cible

Le public principal est francophone, avec une priorité donnée à la France.

Cependant, le contenu ne doit pas être exclusivement centré sur la France.

Le site doit proposer une culture générale réellement internationale, tout en restant particulièrement pertinent pour un utilisateur français.

### Répartition géographique indicative

* **35 % : France**
* **25 % : Europe hors France**
* **20 % : États-Unis et Amérique du Nord**
* **20 % : reste du monde**

Ces pourcentages sont des **objectifs indicatifs**, pas des règles rigides.

La répartition doit également varier selon les catégories.

Par exemple :

* un quiz sur la gastronomie française peut être fortement centré sur la France ;
* un quiz sur les capitales doit être mondial ;
* un quiz sur l'histoire doit avant tout être français mais peut aussi être international mais avec des questions plus simples, doit aussi couvrir plusieurs civilisations ;
* un quiz sur le football doit couvrir différents continents pour du football international, mais se concentrer sur les clubs européens de 1ere division pour du football national;

### Importance de la diversité mondiale

La catégorie « reste du monde » ne doit pas devenir uniquement « Royaume-Uni + Allemagne + Italie ».

Il faut volontairement inclure :

* Afrique ;
* Asie ;
* Amérique latine ;
* Moyen-Orient ;
* Europe de l'Est ;
* Asie du Sud ;
* Asie du Sud-Est ;
* civilisations anciennes ;

L'objectif est d'éviter un biais culturel occidental excessif.

# 5. Difficulté

La difficulté doit être pensée pour un **public généraliste**.

Répartition cible :

* **20 % facile**
* **60 % moyen**
* **20 % difficile**

## Facile

Questions auxquelles une grande partie du public peut répondre.

Exemple :

> Quelle est la capitale de l'Italie ?

## Moyen

Questions nécessitant quelques connaissances ou un peu de réflexion.

Exemple :

> Quel poète est notamment célèbre pour la relation tumultueuse qu'il a entretenue avec Paul Verlaine ? Il est l'auteur des recueils "Illuminations" et "Une Saison en Enfer" 

## Difficile

Questions qui permettent de réellement tester les connaissances d'un joueur cultivé.

Cependant, « difficile » ne doit pas signifier :

* connaissance extrêmement spécialisée ;
* détail obscur ;
* information arbitraire ;
* chiffre précis impossible à retenir ;
* date exacte sans intérêt ;
* personne inconnue du grand public.

Une question difficile doit être **stimulante**, pas artificiellement difficile.

---

# 6. Principe fondamental : faits d'abord, questions ensuite

Le LLM ne doit **jamais être considéré comme la source de vérité**.

Le système doit suivre cette logique :

```text
SOURCE FIABLE
     ↓
FAIT STRUCTURÉ
     ↓
QUESTION
     ↓
VALIDATION
     ↓
PUBLICATION
```

La question est générée à partir d'un fait vérifié.

Elle ne doit pas être générée uniquement à partir de la mémoire du LLM.

---

# 7. Séparation entre faits et questions

Les faits et les questions doivent être stockés séparément.

### Exemple de fait

```text
Sujet : Paris
Propriété : est la capitale de
Objet : France
Source : source fiable
Dernière vérification : 2026-10-01
```

Ce fait peut ensuite produire plusieurs questions différentes.

### Exemple

```text
Quelle est la capitale de la France ?

Dans quel pays se trouve Paris ?

Paris est la capitale de quel pays ?
```

Cela permet :

* de générer plusieurs formulations ;
* de remplacer une question devenue obsolète ;
* de détecter les doublons ;
* de conserver la source originale ;
* de mettre à jour plusieurs questions lorsqu'un fait change.

# 8. Sources de données

Les sources doivent être choisies en priorité pour leur :

* fiabilité ;
* stabilité ;
* qualité ;
* traçabilité ;
* capacité de mise à jour ;
* réutilisabilité.

## Wikidata (source principale)

**Wikidata est la source principale pour les données structurées.**

Elle fournit une base de connaissances collaborative, multilingue et structurée, avec des références permettant de vérifier les informations. Les données sont disponibles pour réutilisation sous CC0.

Avantages pour notre projet :

* API SPARQL pour requêtes complexes ;
* données multilingues (français + anglais + autres langues) ;
* relations entre entités (permet de générer des distracteurs cohérents) ;
* métadonnées riches (dates, catégories, propriétés) ;
* mises à jour communautaires régulières ;
* licence ouverte CC0.

**Pour les MVP 1, 2 et 3, nous nous concentrons exclusivement sur Wikidata.**

D'autres sources pourront être ajoutées ultérieurement selon les besoins identifiés en production.

## Sources complémentaires (post-MVP3)

Ces sources pourront être intégrées à l'avenir si nécessaire :

* data.gouv.fr (données françaises spécifiques) ;
* fédérations sportives officielles ;
* organismes scientifiques ;
* institutions culturelles ;
* bases cinématographiques fiables.

# 10. Génération des distracteurs (QCM)

Pour les modes **PvP** et **Entraînement**, chaque question QCM doit proposer **5 choix** :

* 1 réponse correcte ;
* 4 distracteurs (réponses incorrectes mais plausibles).

## Principe fondamental

**Un bon distracteur doit être plausible mais faux.**

Un joueur qui ne connaît pas la réponse ne doit pas pouvoir éliminer les distracteurs évidents.

## Stratégies de génération via Wikidata

### 1. Même catégorie / même type d'entité

Si la question porte sur une capitale, les distracteurs doivent être d'autres capitales.

**Exemple :**

> Quelle est la capitale de l'Italie ?
> 
> - Rome ✓
> - Milan
> - Florence
> - Naples
> - Venise

**Requête Wikidata :** Récupérer d'autres entités avec la propriété `P31` (instance de) = `Q5119` (capitale).

### 2. Même famille / même domaine

Si la question porte sur un réalisateur français, les distracteurs doivent être d'autres réalisateurs français ou européens.

**Exemple :**

> Qui a réalisé "Amélie Poulain" ?
> 
> - Jean-Pierre Jeunet ✓
> - Luc Besson
> - François Truffaut
> - Jacques Audiard
> - Cédric Klapisch

**Requête Wikidata :** Récupérer d'autres entités avec `P106` (occupation) = `Q2526255` (réalisateur) + `P27` (nationalité) = `Q142` (France).

### 3. Proximité géographique ou temporelle

Pour les questions historiques ou géographiques, utiliser des éléments proches.

**Exemple :**

> En quelle année a eu lieu la Révolution française ?
> 
> - 1789 ✓
> - 1792
> - 1848
> - 1870
> - 1799

**Requête Wikidata :** Récupérer d'autres événements français du XVIIIe-XIXe siècle.

### 4. Relations sémantiques

Utiliser les relations Wikidata pour trouver des entités liées mais distinctes.

**Exemple :**

> Quel fleuve traverse Paris ?
> 
> - La Seine ✓
> - La Loire
> - Le Rhônee
> - La Garonne
> - La Marne

**Requête Wikidata :** Récupérer d'autres fleuves français via `P31` (instance de) = `Q4022` (fleuve) + `P17` (pays) = `Q142` (France).

### 5. Confusion courante

Utiliser des éléments souvent confondus.

**Exemple :**

> Quelle est la plus haute montagne d'Europe ?
> 
> - Le Mont Blanc ✓
> - Le Mont Elbrouz (plus haute d'Europe si on compte le Caucase)
> - Le Mont Rose
> - Le Cervin
> - Le Kilimandjaro (Afrique, confusion courante)

## Critères de qualité des distracteurs

### ✅ Bon distracteur

* plausible sans connaissances préalables ;
* même catégorie que la bonne réponse ;
* ne contient pas d'indices évidents (ex : pas "New York" pour "Capitale Italie") ;
* diversifié (pas 4 variantes de la même chose).

### ❌ Mauvais distracteur

* évidemment faux (ex : "Tokyo" pour "Capitale de l'Italie") ;
* hors catégorie (ex : un acteur dans une liste de réalisateurs) ;
* trop similaire à la bonne réponse (ex : "Rome" et "Roma") ;
* anachronisme flagrant (ex : "Napoléon" pour une question sur la Seconde Guerre mondiale).

## Pipeline de génération des distracteurs

```text
Bonne réponse identifiée
      ↓
Extraction des propriétés Wikidata (type, catégorie, pays, époque, etc.)
      ↓
Requête SPARQL pour trouver entités similaires
      ↓
Filtrage (exclure la bonne réponse, éliminer doublons)
      ↓
Scoring de pertinence (distance sémantique, popularité)
      ↓
Sélection des 4 meilleurs distracteurs
      ↓
Validation (pas de confusion évidente, diversité suffisante)
      ↓
Stockage avec la question
```

## Gestion des cas particuliers

### Questions numériques

Pour des dates ou nombres, générer des distracteurs proches mais distincts.

**Exemple :**

> Combien de départements compte la France métropolitaine ?
> 
> - 96 ✓
> - 95
> - 101
> - 94
> - 100

### Questions avec images

Les distracteurs doivent être visuellement similaires (même type d'objet, même composition).

**Exemple :** Drapeaux avec couleurs similaires, monuments de même style architectural.

# 11. Gestion des variantes de réponses (Daily - Questions ouvertes)

Pour le mode **Daily** (questions ouvertes), le joueur doit taper sa réponse librement.

Le système doit adopter une **politique laxiste** pour accepter les variantes dues à :

* fautes de frappe ;
* fautes d'orthographe ;
* variations linguistiques ;
* synonymes courants.

## Stratégies d'acceptation

### 1. Normalisation de base

Toutes les réponses sont normalisées avant comparaison :

* suppression des accents (optionnel selon contexte) ;
* conversion en minuscules ;
* suppression des espaces superflus ;
* suppression de la ponctuation.

**Exemple :**

> Question : Quelle est la capitale de l'Italie ?
> 
> Accepté :
> - Rome
> - rome
> - ROME
> - Rome.
> - R o m e

### 2. Distance de Levenshtein (fautes de frappe)

Accepter les réponses avec une distance d'édition ≤ 2 pour les mots longs (≥ 5 caractères).

**Exemple :**

> Bonne réponse : "Rome"
> 
> Accepté avec distance = 1 :
> - Róme (faute accent)
> - Romme (double consonne)
> - Roem (inversion lettres)

**Seuil dynamique selon longueur du mot :**

* ≤ 4 caractères : distance maximale = 1
* 5-8 caractères : distance maximale = 2
* ≥ 9 caractères : distance maximale = 3

### 3. Synonymes et variantes linguistiques

Stocker plusieurs réponses acceptées pour chaque question.

**Exemple :**

> Question : Quel est le plus grand pays du monde ?
> 
> Réponses acceptées :
> - Russie
> - Fédération de Russie
> - Russia (anglais)
> - URSS (historiquement, selon contexte temporel)

### 4. Détection des articles et déterminants

Accepter les réponses avec ou sans article.

**Exemple :**

> Question : Quel fleuve traverse Paris ?
> 
> Accepté :
> - Seine
> - La Seine
> - la seine

**Implémentation :** Suppression automatique des articles courants (le, la, les, l', un, une, des) avant comparaison.

### 5. Caractères spéciaux et diacritiques

Politique flexible sur les accents pour éviter de pénaliser les claviers mobiles ou étrangers.

**Exemple :**

> Bonne réponse : "États-Unis"
> 
> Accepté :
> - Etats-Unis (sans accent)
> - Etats Unis (sans tiret)
> - USA (sigle courant)
> - Amérique (synonyme acceptable selon contexte)

### 6. Cas particuliers : noms propres composés

Accepter les formes courtes courantes.

**Exemple :**

> Bonne réponse : "Victor Hugo"
> 
> Accepté :
> - Victor Hugo
> - Hugo (si non ambigu dans le contexte)
> - V. Hugo

## Pipeline de validation des réponses

```text
Réponse joueur
      ↓
Normalisation (minuscules, suppression espaces/ponctuation)
      ↓
Suppression des articles
      ↓
Comparaison exacte avec réponses acceptées
      ↓
SI pas de match exact → Calcul distance de Levenshtein
      ↓
SI distance ≤ seuil → ACCEPTÉ
      ↓
SINON → REFUSÉ
```

## Cas limites et règles métier

### Accepter généreusement les variantes culturelles

**Exemple :**

> Question : Capitale de la Côte d'Ivoire ?
> 
> Accepté :
> - Yamoussoukro (capitale officielle)
> - Abidjan (capitale économique, confusion courante → accepter avec message éducatif)

**Implémentation :** Réponse principale = Yamoussoukro, mais accepter Abidjan avec feedback : *"Yamoussoukro est la capitale officielle depuis 1983, bien qu'Abidjan reste la capitale économique."*

### Rejeter les réponses trop vagues

**Exemple :**

> Question : Quel acteur a joué Iron Man ?
> 
> Refusé :
> - Robert (trop vague)
> 
> Accepté :
> - Robert Downey Jr
> - Downey Jr
> - RDJ

### Gestion des homonymes

Si plusieurs réponses valides existent, accepter toutes.

**Exemple :**

> Question : Quelle ville française s'appelle "la cité des Ducs" ?
> 
> Accepté :
> - Dijon
> - Nantes (si les deux sont historiquement correctes)

**Implémentation :** Vérifier en amont qu'une question n'a pas plusieurs réponses également valides (sinon, reformuler la question).

## Stockage des variantes dans la base de données

Chaque question doit avoir :

* **1 réponse canonique** (affichée dans les explications) ;
* **N réponses acceptées** (liste de variantes valides) ;
* **Seuil de distance de Levenshtein** (par défaut ou personnalisé).

**Schéma exemple :**

```json
{
  "question_id": 1234,
  "question_text": "Quelle est la capitale de l'Italie ?",
  "canonical_answer": "Rome",
  "accepted_answers": [
    "Rome",
    "Roma",
    "rome"
  ],
  "levenshtein_threshold": 1,
  "strip_articles": true
}
```

# 12. Génération des questions

Le pipeline de génération doit suivre les étapes suivantes :

```text
Source fiable
      ↓
Extraction des données
      ↓
Création d'un fait structuré
      ↓
Évaluation de l'intérêt du fait
      ↓
Génération de questions candidates
      ↓
Génération des réponses
      ↓
Génération des distracteurs
      ↓
Validation factuelle
      ↓
Détection des ambiguïtés
      ↓
Détection des doublons
      ↓
Évaluation de la difficulté
      ↓
Catégorisation
      ↓
Score de qualité
      ↓
Publication
```

# 13. Qualité des questions

Chaque question doit être évaluée selon plusieurs critères.

## Exactitude

La réponse doit être factuellement correcte.

## Clarté

La question doit être immédiatement compréhensible.

## Absence d'ambiguïté

Une question ne doit pas pouvoir avoir plusieurs réponses correctes.

## Intérêt

La question doit apporter quelque chose au joueur.

Éviter les questions générées uniquement parce qu'une information existe dans une base de données.

## Accessibilité

Le joueur moyen doit pouvoir comprendre la question sans connaissances spécialisées.

## Vérifiabilité

La réponse doit pouvoir être reliée à une source.

## Bonne formulation française

Éviter :

* traductions littérales ;
* formulations artificielles ;
* anglicismes inutiles ;
* phrases trop longues ;
* formulations maladroites
